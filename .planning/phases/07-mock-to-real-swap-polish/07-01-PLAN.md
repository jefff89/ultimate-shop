<objective>
Deliver the Phase 7 vertical slice: the landing page renders REAL catalog data end-to-end. This requires three pieces that are only valuable together — (1) seed the database with a realistic dataset so there is data to show and paginate, (2) build the real data source (`catalog.source.real.ts`) that proxies the Phase 6 NestJS endpoints through the established `createServerFn` + `@/utils/fetch` pattern with the Zod egress gate, and (3) flip the one-line seam in `catalog.ts` from mock to real. Also add `scrollRestoration: true` to the router as future-proof infrastructure.

Purpose: This is the integration payoff of the whole milestone. The seam was engineered across Phases 2/4/6 so that the swap is a re-export flip; the only genuinely new code is the real fetcher and a seed routine. After this plan, a developer running both servers sees real DB products in the grid and rails — something impossible before (the table had 1 row and the seam pointed at the mock).

Output: `seed-catalog.ts` (+ npm script wiring), `catalog.source.real.ts`, `catalog.source.real.test.ts`, a one-line edit to `catalog.ts`, and a one-option edit to `router.tsx`.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser -> Start server | Same-origin only (CSP `connect-src 'self'`); the browser never calls :3002 directly |
| Start server -> NestJS API | `createServerFn` handler proxies to `API_URL` and forwards the cookie |
| NestJS API -> Postgres | Parameterized keyset query; opaque cursor decoded + validated server-side |
| Real backend response -> UI | Zod `.parse()` egress gate in catalog.source.real.ts before any data reaches a card |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-01 | Tampering | Cursor passed to `GET /products` | mitigate | Backend `decodeCursor` validates -> 400 (Phase 6); the real fetcher lets the 400 throw (no swallow into empty page) so a tampered cursor surfaces as an error, not silent data loss |
| T-07-02 | Information disclosure | Real backend response -> card render | mitigate | Every fetcher ends with the frozen 9-field `.parse()`; field-by-field projection already enforced backend-side; FE parse is defense-in-depth and the SC4 drift gate — never bypass it |
| T-07-03 | Spoofing | Cross-origin credentialed request | mitigate | Browser stays same-origin via the `createServerFn` proxy (CSP `connect-src 'self'`); CORS restricted to :3001 (Phase 6) — no direct browser fetch to :3002 |
| T-07-04 | Tampering | Seed routine writing to product/category tables | accept | Seed is a dev-only operational script run manually by the developer against the local DB; not exposed over HTTP; no untrusted input |
| T-07-05 | Injection | Untrusted image URL from seeded `primaryImageUrl` | mitigate | Seed emits only https URLs; `SafeImage` (Phase 5) rejects non-https/`javascript:`/`blob:` schemes regardless |
| T-07-SC | Tampering | npm/bun installs (supply chain) | mitigate | Phase 7 adds NO new runtime packages (RESEARCH Package Legitimacy Audit); seed deliberately avoids adding @faker-js/faker to shop-back. If any package install is introduced, a blocking-human legitimacy checkpoint is required first |
</threat_model>
