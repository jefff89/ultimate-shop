## Motion & Loading Contract (phase-specific — LOAD-BEARING)

This is the core of Phase 5. Values are LOCKED by the developer. Executor must implement exactly these; checker/auditor validate against them.

### 1. Skeletons (MOT-01)

**Pattern:** keep the existing **pulse** pattern. No shimmer, no spinner.

| Property | Value |
|----------|-------|
| Animation | `animate-pulse` (Tailwind built-in) |
| Fill color | `bg-zinc-100` |
| Corner radius | match the real element (`rounded-xl` for cards, `rounded-full` for chips) |
| Container a11y | `role="status"` + `aria-busy="true"` + an `sr-only` loading label |
| Box sizing | **pixel-identical** to the real element it replaces (reserve the same width/height) so swapping skeleton → content causes **zero CLS** |

**Skeleton inventory for this phase:**

| Skeleton | Stands in for | Required box dimensions |
|----------|---------------|-------------------------|
| Rail skeleton | `Rail` row cards | `h-56 w-44 shrink-0 animate-pulse rounded-xl bg-zinc-100` (EXISTING in `Rail.tsx` — reuse as the canonical pattern, do not change) |
| Grid card skeleton (NEW) | `ProductCard` | Outer `rounded-xl border border-zinc-200`; an `aspect-square bg-zinc-100 animate-pulse` image well + a body block matching the `gap-1 p-3` text area (a `text-sm` name line + a `text-base` price line height). MUST match `ProductCard`'s rendered box so grid CLS stays ≤ 0.1. |
| Grid "loading more" (EXISTING) | next-page fetch | keep "Loading more…" text row (`py-6 text-center text-sm text-zinc-400`) — already non-CLS, no change required |
| Hero skeleton (OPTIONAL) | `Hero` | Hero is a static SSR gradient with no remote fetch; a skeleton is **optional**. If added, reserve the hero's `rounded-2xl` box and `py-14 sm:py-20` height. |

**Canonical skeleton container snippet** (match `Rail.tsx` conventions; no semicolons, single quotes):

```tsx
<div role="status" aria-busy="true" className="...reserve-real-dimensions...">
  {/* animate-pulse bg-zinc-100 blocks sized to the real element */}
  <span className="sr-only">Loading products…</span>
</div>
```

### 2. Lazy images + reserved dimensions (MOT-02)

| Property | Value |
|----------|-------|
| Loading | `loading="lazy"` on every catalog/feed image (EXISTING on `ProductCard`) |
| Reserved dimensions | explicit `width={400} height={400}` + `aspect-square` well (EXISTING). Keep — this is what holds CLS ≤ 0.1 |
| Target | **CLS ≤ 0.1** (Lighthouse), including when an image errors |

**Broken/dead-URL fallback (the MOT-02 gap to close):**

`SafeImage` today validates the URL **scheme** but has **no `onError` handling** — a valid `https` URL that 404s/hangs renders the browser's broken-image glyph. Close this gap:

| Aspect | Contract |
|--------|----------|
| Trigger | image `onError` (load failure of an otherwise scheme-valid URL) **or** a rejected/absent src |
| Rendered fallback | the existing neutral **`bg-zinc-100` reserved box** (same `aspect-square` / `width`×`height`) with a **centered muted lucide icon** (`ImageOff`, or `Image`, in `text-muted-foreground`) |
| Forbidden | native broken-image glyph; any layout shift; any error/destructive coloring; a hang/spinner |
| Box invariant | reserved dimensions stay **identical** between loading, loaded, and fallback states → CLS ≤ 0.1 |
| Icon a11y | fallback icon is decorative (`aria-hidden="true"`); the image `alt` (product name) is preserved on the wrapper for screen readers |
| Implementation note | requires `SafeImage` (or a thin wrapper) to hold `onError` state and switch to the fallback render. Keep the existing scheme-validation logic intact (still reject `javascript:`/`blob:`/`file:`, allow same-origin/https/`data:image`). |

### 3. Reveal-on-scroll (MOT-03)

Subtle fade + small rise, **motion-safe gated**, with a fully-visible SSR/no-JS baseline.

| Property | Value |
|----------|-------|
| Effect | opacity `0 → 1` **plus** `translateY(8px → 0)` |
| Duration | ~400ms |
| Easing | ease-out |
| Stagger | slight per-item stagger within a rail/grid (incremental delay per item) |
| Gating | `motion-safe` only (Tailwind `motion-safe:` variant / `prefers-reduced-motion`). Reduced-motion users get **no** animation — content appears in final state immediately |
| **SSR / no-JS baseline** | rendered markup MUST be **fully visible, final position** (`opacity: 1`, no transform). The reveal is **progressive enhancement** applied *after* hydration (e.g. IntersectionObserver toggling a data-attribute/class). **Never** ship an inline `opacity: 0` / initial hidden state that would hide content with JS disabled |
| Hydration | no mismatch — server HTML and first client render must agree (both fully visible); the animation class is added only post-mount when motion is safe and the element enters the viewport |

**Implementation pattern (required):**
1. Element renders visible by default (opacity 1, no transform) — SSR-safe, no-JS-safe.
2. After mount, JS adds a `motion-safe`-gated "pre-reveal" state (only if motion is safe) and an IntersectionObserver flips it to "revealed," producing the fade+rise.
3. Per-item delay produces the stagger.

> Forbidden: inline `style={{ opacity: 0 }}` on initial SSR render; un-gated animation; animating layout properties.

### 4. Card hover lift (MOT-04)

Restrained, tasteful elevation on `ProductCard`. The card itself does **not** lift today — this phase adds it.

| Property | Value |
|----------|-------|
| Transform | `translateY(-2px)` on hover |
| Shadow | `shadow-sm → shadow-md` on hover |
| Duration | ~200ms transition |
| Animated properties | **transform / opacity / box-shadow only** — NO layout-affecting properties (no width/height/margin/top) |
| Keep existing | the image `group-hover:scale-105` (existing `transition-transform duration-300` inside the image well) — **retain it**, the new lift is on the outer `<article>` |
| Restraint | one small step of elevation; no large jumps, glow, color shifts, or rotation |

**Target element:** the outer `<article className="group …">` in `ProductCard.tsx` gains a base `shadow-sm` and `transition` plus `hover:-translate-y-0.5 hover:shadow-md` (≈ `-2px`). Should also be `motion-safe`-respecting where practical (hover transitions are low-risk, but gate the transform under `motion-safe:` to honor reduced-motion users).
