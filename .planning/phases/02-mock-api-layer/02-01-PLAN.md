<objective>
Deliver the core vertical slice of the mock-API layer: a seeded in-memory catalog dataset, an in-memory keyset-pagination function `fetchCatalogPage` that returns `CatalogPage<CatalogProductCard>` pages byte-compatible with the frozen Phase 1 contract, and the single swappable seam (`data/catalog.ts`) that UI phases import. The slice is proven end-to-end by the keystone full-traversal test (no skips/dupes across page boundaries) plus contract conformance.

This plan covers MOCK-01 (pages conform to `CatalogPage`), MOCK-02 (large/varied dataset across many pages), and MOCK-03 (swappable behind one seam) for the happy path. Plan 02 adds the defense-in-depth and edge tests (tiebreaker, tamper rejection, determinism, variety assertions).

Purpose: Unblock Phases 3-5 (the infinite grid and rails import `fetchCatalogPage` from the seam) without a backend, and guarantee the mock enforces the same `(createdAt DESC, id DESC)` keyset semantics the real endpoint (Phase 6) will mirror.

Output: `shop-front/src/data/catalog.source.mock.ts`, `shop-front/src/data/catalog.ts`, `shop-front/src/data/catalog.source.mock.test.ts`, and the `@faker-js/faker` exact-pinned devDependency in `shop-front/package.json`.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| UI → fetchCatalogPage(cursor) | The `cursor` string is the only structured untrusted input crossing into the mock data layer (in Phase 3+ it originates from a prior page's `nextCursor`, but could be tampered/crafted). |
| package install (bun add) | Adding `@faker-js/faker` pulls third-party code into the build. |

This is a frontend-only, in-memory mock with no real network, no auth, no DB, and no user-supplied free-text input. The realistic threat surface is narrow; threats below are proportionate to that.

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Tampering | `fetchCatalogPage` cursor arg | mitigate | `decodeCursor` (Phase 1 codec) validates structure + date and throws `InvalidCursorError` on a tampered/garbage cursor. The mock MUST let it propagate — no try/catch returning an empty page (RESEARCH anti-pattern). Verified by Plan 02's "rejects tampered cursor" test. |
| T-02-02 | Information Disclosure | cursor contents / internal fields | mitigate | Cursor carries only `(createdAt, id)` base64url via the shared codec — no offsets/table names. The card built by `toCard` exposes only the 9 contract fields; `createdAt` and sort internals are never placed on the card (CONT-02). |
| T-02-03 | Tampering (supply chain) | `bun add -d @faker-js/faker` | mitigate | faker tagged [ASSUMED] (slopcheck sandbox-blocked); Task 1 is a blocking-human checkpoint requiring npmjs.com verification before install, pinned exact to prevent silent sequence drift. T-02-SC. |
| T-02-04 | Denial of Service | mock image URLs vs CSP | accept | faker `urlLoremFlickr` emits `https:` URLs; the app CSP is `img-src 'self' data: https:` so they are permitted. No mitigation needed; documented so a future non-https mock host would be caught. |

There is no Spoofing/Repudiation/Elevation surface in an unauthenticated in-memory mock with no identity, no audit log, and no privileged operation — deliberately omitted rather than invented.
</threat_model>
