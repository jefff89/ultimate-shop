<frozen_cross_side_decisions>
These two decisions are resolved HERE and frozen for all downstream phases (record them verbatim in the SUMMARY's "Artifacts" section):

- **D-06 — `CatalogProductCard.price` shape:** The contract field is **`price: z.number()` (non-nullable)**. A card must always render a price. The backend projection (Phase 6) computes it as `basePrice` when set, else the minimum active `ProductVariant.price` (a "from" price); products with neither a `basePrice` nor any variant price are excluded from the listing projection. The contract does not encode the source — only that a numeric price is always present.
- **Decimal-as-string landmine:** TypeORM returns `decimal` columns (`basePrice`, `rating`) as JS **strings** at runtime; the FE mock emits numbers. The frozen wire shape is **`z.number()`** for both `price` and `rating`. The backend (Phase 6) is responsible for converting decimal strings to numbers in its projection mapper BEFORE calling `.parse()`. Do NOT use `z.string()` for these fields and do NOT make the contract `z.coerce.number()` — keep the contract a plain `z.number()` so the FE mock validates without coercion and the BE owns the conversion at its boundary.
</frozen_cross_side_decisions>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → server (future cursor param) | The `cursor` query value is attacker-controlled untrusted input; it is decoded and its tuple feeds a future keyset WHERE clause (Phase 6). |
| DB row → API response (card projection) | The contract is the gate on what Product fields cross into a client-visible card. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | Tampering | `decodeCursor` in shared/cursor.ts | mitigate | decodeCursor validates the decoded tuple shape (non-empty string createdAt parseable as date + non-empty string id) and throws on mismatch, so a tampered/garbage cursor cannot become a malformed tuple that flows into a query (Phase 6 binds it as a parameter, never string-concatenates). |
| T-01-02 | Information disclosure | cursor opaque encoding | mitigate | Cursor is base64 of (createdAt,id) only — no table names, no offsets, no internal numeric keys; leaks no DB internals (CONT-03). |
| T-01-03 | Information disclosure | CatalogProductCardSchema field set | mitigate | The card schema freezes EXACTLY the 9 lean fields; internal columns (basePrice, totalStock, attributes, categoryId, variant data) are not in the shape, so the projection contract cannot leak them. |
| T-01-04 | Information disclosure | cursor enumeration | accept | A (createdAt,id) cursor is inherently sequential/guessable, but the catalog is public read-only browse data with no per-user authorization — enumeration grants no privilege. Low risk, accepted. |
| T-01-SC | Tampering | `bun install zod` (Plan 02) | n/a here | No package install in this plan; the supply-chain checkpoint lives in Plan 02 where zod is added to shop-back. |

No high-severity threats in this plan; all are mitigated or accepted with rationale.
