<objective>
Establish the composed landing feed: a hero at the top of the homepage and a Featured rail
that renders `isFeatured` products above the existing infinite grid — the first real vertical
slice of Phase 4. This plan also lays the shared rail infrastructure (a presentational `Rail`
shell with distinct loading/empty/error states, and isolated rail query-option factories behind
the Phase 2 data seam) that the Trending and Categories rails (Plans 02, 03) build on.

Purpose: A shopper opening the homepage sees a real composed feed — hero plus a Featured rail —
sitting above the working infinite grid, with the rail fetched on a query key fully isolated from
the grid's cursor stream (FEED-05, the load-bearing requirement).

Output: feed.query.ts (rail factories + seam fetchers), Rail.tsx, Hero.tsx, FeaturedRail.tsx,
LandingFeed.tsx, a `Category` shape + categories fetcher seam stub for Plan 03, and a modified
index.tsx that renders the feed above the grid.
</objective>

<phase_goal>
**As a** shopper, **I want to** land on a homepage that opens with a hero and a Featured rail above the scrolling grid, **so that** I see curated merchandising immediately instead of an undifferentiated wall of products.
</phase_goal>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| mock seam → rail UI | Product/category data (names, image URLs) flows from the mock (future real backend) into rail JSX |
| rail query → route loader/page | A rail fetch can fail; failure must not take down the route or the grid |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | Tampering/XSS | Rail item + category name rendering (Rail.tsx, FeaturedRail.tsx, Hero.tsx) | mitigate | Render all product/category/hero text only as escaped JSX children; zero `dangerouslySetInnerHTML` (reuse Phase 3 escaped-text pattern) |
| T-04-02 | Tampering/XSS | Untrusted image URLs in rail cards / hero | mitigate | Images render ONLY through `SafeImage` (rejects javascript:/blob:/non-https); reuse Phase 3 ProductCard which already does this; prefer CSS background for hero |
| T-04-03 | Information disclosure | Rail error state | mitigate | Error branch shows fixed generic copy ("Couldn't load Featured."), never interpolates the caught error/stack into the DOM |
| T-04-04 | Denial of service | Unbounded rail payload | mitigate | RAIL_LIMIT caps featured/trending fetch length; categories list is a fixed small seeded set |
| T-04-05 | Denial of service | A failing rail crashing the page / disturbing the grid cursor stream | mitigate | useQuery isolates rail failure to the Rail error branch (fail-closed, no throw); loader uses non-throwing `prefetchQuery` so a rail fetch failure never rejects the route; rail keys `['feed',*]` share no state with `['catalog']` (FEED-05) |
| T-04-SC | Tampering | npm/pip/cargo installs | mitigate | No new dependencies added this plan; if any install is introduced, halt and run legitimacy gate |
</threat_model>
