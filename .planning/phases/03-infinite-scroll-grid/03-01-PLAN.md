<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| catalog data source → React render | `primaryImageUrl`, `name`, `rating`, `price` come from the (currently mock, later real) catalog and are rendered into the DOM |
| pagination cursor → fetchCatalogPage | the `pageParam`/cursor string is fed back into the seam fetch as the keyset cursor |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Tampering/Injection | `primaryImageUrl` rendered as `<img src>` | mitigate | Render product images ONLY through existing `SafeImage` (rejects `javascript:`/`blob:`/`file:`/non-https schemes, handles null) — Task 2 acceptance grep enforces SafeImage usage, no raw `<img>` for product images |
| T-03-02 | Tampering (XSS) | product `name` / text fields in `ProductCard` | mitigate | Render all text via JSX children only; `dangerouslySetInnerHTML` is forbidden (Task 2 acceptance: grep returns nothing) |
| T-03-03 | Denial of Service | unbounded retained pages on deep scroll (client memory) | mitigate | `maxPages: 6` cap in `catalogInfiniteQueryOptions` (GRID-03); Task 1 acceptance greps the cap |
| T-03-04 | Tampering | abusable/garbage pagination cursor passed to the seam | accept | Already mitigated upstream: `fetchCatalogPage` decodes via the shared cursor codec which validates and throws `InvalidCursorError` on tampered input, and clamps `limit` to MAX_PAGE_SIZE (Phase 2). No new surface added here; pageParam always originates from a prior server-issued `nextCursor` |
| T-03-05 | Information Disclosure | error/loading states leaking internal details | accept | This plan renders no error UI (Plan 02 owns end-of-list/error surface); the grid renders only contract-projected card fields (CONT-02 guarantees no internal columns leak onto a card) |
| T-03-SC | Tampering | npm/bun installs | accept | No new dependencies added in this plan (uses installed `@tanstack/react-query`, existing `SafeImage`, faker is dev-only from Phase 2). No install task → no slopcheck checkpoint required |

No `high`-severity threat is left unmitigated.
</threat_model>
